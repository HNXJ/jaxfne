## TFNE2-01 — S14 exclusions

Exclusion semantics were inverted, in both directions of the guarantee: an
exclusion over a realized projection raised, and an exclusion matching nothing
was a silent no-op.

`tfne/2` S14 defines exclusion as subtraction over projection identities: rule
expansion produces `G_0`, exclusions resolve to `E_-` with `E_- subset G_0`, and
`G = G_0 \ E_-`. An exclusion matching no generated projection is
`E_EXCLUSION_UNKNOWN`.

Implemented in `realize()`:

- Subtraction moved ahead of edge compilation and onto projection identities. The post-compilation veto scan over realized edges is gone.
- An exclusion names no mechanism in the grammar, so it resolves to every identity in `G_0` sharing its `(src, dst)` route. Recorded at the change site.
- A relation losing every route emits nothing; a relation losing some routes emits one connection per surviving route under a route-qualified key, so subtraction is per identity rather than per relation. A relation losing no routes emits exactly as before, preserving existing keys and edge ordering in `I`.
- An exclusion whose routes match nothing in `G_0` raises with `E_EXCLUSION_UNKNOWN` in the message. The typed failure classes of S25 remain TFNE2-07; only this clause's condition is enforced.
- `_scope_pairs` extended to resolve `!>` / `!<` directions, which previously fell through to the bidirectional branch.

## TFNE2-02 — S6/S7 instance addressing

`A^n` realized `A.0 ... A.(n-1)`. `tfne/2` S6 defines `A^n = {A.1 ... A.n}`.
Every replicated path in `I` therefore named a different instance than the
language did.

`_expand_replicate` now indexes from 1. No other replication index assumption
exists in the module (checked: the only other `Replicate` sites are the parser's
count validation and `_emit_expr`).

## S10 opened (not fixed)

Found while reading the relation builder for TFNE2-01, then measured.

`tfne/2` S10: a mixed-rule ordered chain `A O[k] B O[j] C` normalizes to the
adjacency-labelled sequence `(A,k,B,j,C)`, and **each rule applies only to its
own adjacency**.

Observed at entry state — the resolver accumulates left operands:

```
key=r0:O[ff]:A>B           pre_scopes=('A',)     post_scopes=('B',)
key=r1:O[ff]:A O[ff] B>C   pre_scopes=('A','B')  post_scopes=('C',)

realized scope-level projections: [('A','B'), ('A','C'), ('B','C')]
n_edges = 12          (S10 gives [('A','B'), ('B','C')] and 8)
```

The compiler realizes `A>C`, which the source never declares. The corpus
`CORTEX` definition `L1 O[ff] L2 O[ff] ... O[ff] L6` therefore realizes every
layer onto every later layer — 15 inter-laminar projections where the
specification declares 5 — rather than the laminar chain.

This is a meaning bug of the same class as TFNE2-01 and TFNE2-02, not a missing
feature. It was outside the authorized scope of this step and is queued as
**TFNE2-08**, marked do-first. Fixing it will change `CORTEX` and `NESTED`
corpus edge counts.
