- Fixed `simulate()` and `simulate_batch()` recording `recurrent_backend: "dense"` in the run metadata and manifest when the edge-list kernel ran (homeostasis, HDP, or a model whose edges live only in `params["edge_list"]`); the metadata now records the backend that ran, and the runtime report keeps the requested value. An explicit model-level `recurrent_backend="dense"` is now refused instead of replaced under homeostasis, under an engaged HDP rule in `simulate()`, and under any `enable_hdp=True` in `simulate_batch()` (which always runs the HDP edge kernel). Spikes, voltages and HDP and homeostasis state are unchanged (ISSUE_LOG P-062).
- Fixed `simulate_batch()` running a model with nonzero edge `delay_steps` on the dense backend and dropping the delays; an explicit `recurrent_backend="dense"` is now refused there, as in `simulate()`, and `"auto"` runs edge_list. Batch outputs of such models change (ISSUE_LOG P-063).
- Fixed `simulate_batch()` ignoring `hdp_rule_params` for a registered HDP rule (it ran the rule at its zero-gain defaults, and `ephaptic_field` was refused); the parameters now reach the kernel as in `simulate()`, and so does `plasticity_mask`, which the same call also dropped. Batch outputs of registered rules with parameters or a mask change (ISSUE_LOG P-064).
- Fixed `simulate()` and `simulate_batch()` with `enable_homeostasis=True` running a model whose edges carry nonzero `delay_steps` and dropping the delays; the homeostasis kernel has no delay path, so these runs now raise "enable_homeostasis has no finite-delay path". Runs with zero delays are unchanged (ISSUE_LOG P-065).
