## Canonical public position (private anchor)

Public entry points must remain consistent with this wording (not pasted
verbatim everywhere):

> JaxFNE is a Python package for biophysical source-field modeling, coupling
> neural activity and biophysical state with plasticity, network geometry, and
> population- and field-scale dynamics. Neural models can be defined at
> different levels of biological detail and reduced when computational
> efficiency is required.

This file is private. It extends that public position with **execution
architecture** (W15), **scientific / developmental model architecture** (W16),
and **downstream empirical evidence** (W17 / §9 Jomission). Nothing below is a
claim of current implementation unless explicitly marked DONE.

## 0. What "thinnest, flawless, bugless" has to mean here

"Flawless" is not a testable predicate, so this programme does not use it as an
acceptance criterion. It is decomposed into four things that can each fail:

1. **No silent scientific failure.** Every path that can swallow an error either
   raises, or records a counted, named rejection reason that reaches the caller.
2. **No unexplained canonical cost.** Every canonical-runtime allocation or
   operation scaling worse than the information it carries is classified, and
   every AVOIDABLE one is either reduced or justified in writing.
3. **No public surface promising what does not exist.** Rendered docs and public
   API describe implemented behaviour only.
4. **Observable equivalence under a declared tolerance.** Every reduction is
   accepted against a named observable and a stated epsilon, or is bit-exact.

A release is done when its gates pass with receipts, not when it feels clean.
`UNKNOWN` is never a pass. Same rule that governed the v0.4.21 seal.

### 1.1b Tensor-allocation map, N=1000 (the map that decides v0.4.23)

`construct(configuration().network(n=1000).emitter().field().probe(n_contacts=8))`.
"Distinct" is the count of unique values in the array, i.e. how much information
the allocation actually carries.

| tensor | shape | dtype | MB | distinct values |
| --- | --- | --- | --- | --- |
| `emitter.W` | (1000, 1000) | float32 | 4.000 | **3** |
| `edge_list.pre` | (999000,) | int32 | 3.996 | 1000 |
| `edge_list.post` | (999000,) | int32 | 3.996 | 1000 |
| `edge_list.weight` | (999000,) | float32 | 3.996 | **2** |
| `edge_list.receptor_index` | (999000,) | int32 | 3.996 | **2** |
| `edge_list.tau_ms` | (999000,) | float32 | 3.996 | **2** |
| `edge_list.delay_steps` | (999000,) | int32 | 3.996 | **1** |
| `positions` | (1000, 3) | float32 | 0.012 | 1000 |
| `emitter.{a,b,c,d,drive,sign,u0}` | (1000,) each | float32 | 0.004 each | 1-3 each |
| `emitter.v0` | (1000,) | float32 | 0.004 | 999 |
| **total persistent** | | | **28.020** | |

Reading of this map:

- **~16 MB of 28 MB (57%) is class-shared data materialised per edge.**
  `weight`, `receptor_index`, `tau_ms` carry 2 distinct values each; `delay_steps`
  carries **one** - 3.996 MB storing a single repeated integer. These are the
  `theta_class` + index case, not per-edge state.
- `emitter.W` carries 3 distinct values across 10^6 float32 entries.
- Per-neuron parameters are already small but equally class-shared: every one of
  `a,b,c,d,drive,sign,u0` has 1-3 distinct values. Only `v0` (999 distinct,
  jittered initial condition) is genuinely per-neuron.
- `pre`/`post` are structural. For all-to-all they are a deterministic
  enumeration and need not be stored at all.

Simulate-time recording, same network:

| duration / dt | T | recorded tensors | total |
| --- | --- | --- | --- |
| 100 ms / 0.1 ms | 1000 | `V_m`, `spikes`, `sources` at (T,N) float32 + `time_ms` | 12.004 MB |
| 200 ms / 0.5 ms | 400 | same | 4.802 MB |

Recording is O(TN), not O(TE) - the feared `T x E` edge-current traces are not
in the default path. One cheap win visible here: `spikes` is float32 at (T,N),
where bool or int8 would be 4x smaller.

### 1.1c Sparsity levers exist but are unreachable, silently inert, or additive

Bounded-degree connectivity is present and, once reachable, correct:
`_make_sparse_within_area_edges` builds an edge list directly from `p_connect`,
and connection rules support `max_in_degree` with spatially-localized sampling.
The 2026-09-08 measurement (superseding the earlier "100x sparsity request had
no effect" entry, which over-generalised from a single route) found the machinery
works but is gated behind three distinct silent-failure modes plus one design
decision.

**D1 -- `max_in_degree` is unreachable through the documented API.**
`_config.Configuration.connections()` always writes `"spatial_sigma": None` into
the rule entry (`jaxfne/_config.py:744`), so
`float(rule.get("spatial_sigma", 0.1))` in `jaxfne/connectivity.py:507` receives
`None`, not the default, and raises
`TypeError: float() argument must be a string or a real number, not 'NoneType'`.
Every `connections(..., max_in_degree=K)` call crashes unless the caller also
passes an undocumented `spatial_sigma=`. Classic dict-default-vs-explicit-None.

**D2 -- without a resolvable `mechanism=`, `max_in_degree` is ignored and the
rule doubles the network.** `_construct_core.py:658` only takes the
mechanism-aware compiler when *every* rule declares a resolvable mechanism;
otherwise `_compile_connection_rules` runs and drops `max_in_degree`. Measured
at N=1000, `connections(max_in_degree=100)` with no mechanism produced
E = 1,998,000 and max in-degree 1998 -- a 10x sparsity request yielded a 2x
*denser* network, with no warning.

**D3 -- `p_connect=0.0` is falsy and therefore ignored**, yielding full dense
N(N-1). A legitimate "suppress baseline recurrence" request cannot be expressed.

**D4 (design, not defect) -- `.connections()` is additive over an
unsuppressible dense default.** `max_in_degree` caps the *rule's* contribution
to exactly N*K, but the base recurrent set remains, so total
E = N(N-1) + N*K. Reaching E = O(N*K) today requires the accidental combination
`.connectivity(p_connect=0.001)` + `.connections(max_in_degree=K,
spatial_sigma=0.1)`.

Route dependence of `p_connect` at N=1000, p=0.01 (measured):

| route | E | verdict |
| --- | --- | --- |
| `.network(n=1000, p_connect=0.01)` | 999,000 | inert |
| `.column(...).connectivity(p_connect=0.01)` | 10,186 | effective |

`.network()` falls through to `make_eig_network` /
`_default_eig_connectivity`, which materialises dense all-to-all unconditionally
(`_construct_core.py:510-540`); a `RuntimeWarning` fires at N >= 5000 but only
warns. A recorded instance: 100,000 neurons with `p_connect=0.0005` still built
a dense (n,n) matrix (~40 GB) and ran ~370 s.

Bounded-degree scaling, once D1-D4 are worked around (measured, seed=1,
`.column()` route, `spatial_sigma=0.1`):

| N | p_connect | K_max | E | max in-deg | E/N | total | `emitter.W` |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1000 | 0.001 | 100 | 101,020 | 106 | 101 | 6.47 MB | 4.00 MB (62%) |
| 4000 | 0.001 | 100 | 415,845 | 113 | 104 | 74.16 MB | 64.00 MB (86%) |
| 1000 | 0.0 | 100 | 1,099,000 | 1099 | 1099 | 30.42 MB | 4.00 MB |
| 4000 | 0.0 | 100 | 16,396,000 | 4099 | 4099 | 457.68 MB | 64.00 MB |

E = O(N*K_max) is therefore already realised. The residual O(N^2) term is
`emitter.W` alone, and it dominates at 86% of construct memory by N=4000. It is
retained below `_SPARSE_DIRECT_N = 5000` (`jaxfne/_construct_population.py:279`)
by an explicitly tested invariant -- `test_below_threshold_keeps_dense_W`
(`tests/test_connectivity_scaling.py:96`) asserts the dense path is preserved.
Removing it means retiring a test that currently encodes the opposite intent,
which is a v0.4.23 decision, not a v0.4.22 one. **Do not delete that test yet.**
It is evidence of existing intentional semantics. W10 must first establish
`U_W` -- every reader of `emitter.W` -- and the exact replacement requirement
for each, before the invariant is retired.

**Consequent restatement of the programme headline.** v0.4.23 is not "make
bounded-degree connectivity edge-native" -- that exists and is correct. It is:

- v0.4.22: make the connectivity controls reachable (D1), composable (D4),
  and non-silent (D2, D3); measure and classify (W10/W11); record external
  execution-architecture lessons (W15 study, no interoperability); define the
  scientific / developmental programme in writing (W16, not implemented).
- v0.4.23: remove `emitter.W`, the last O(N^2) residue; make realized topology
  authoritative and backend layouts execution-specific (W15 principle 1-3);
  optional minimal JDNA `evolve` substrate only if semantics and tests complete.
- v0.4.24: bounded augmentation, Neurobiophysical Geometry, pseudo-
  neurogeneration under explicit error bounds (W16.5–W16.6).

## 2. Release sequence (truth → exact representation → bounded augmentation)

Each release contains only changes whose risk class matches the evidence
available at that point. Two axes govern the programme:

1. **Execution architecture** (W15): specification separable from backend layout;
   efficient simulation of a *fixed* realized model.
2. **Scientific / developmental architecture** (W16): models that may *develop,
   evolve, and change scale* — not only execute once instantiated.

Optimising first and measuring after is the failure mode this ordering exists
to prevent.

### 2.1 v0.4.22 — TRUTH + MEASUREMENT

- Controls mean what they request (W13 connectivity truth; backend refusal).
- No silent scientific failure (W1, W2, W3 classification).
- Public descriptions truthful (W4/W5; canonical public position).
- Computational and state costs measured (W8, W10, W11).
- Downstream mechanism truth: semantics + measurement design (W17; Jomission §9).
- Ecosystem position understood (W15 study; no SONATA interoperability).
- **Developmental concepts defined in this roadmap, not implemented.**

Non-goals: representation reduction, approximation, `G` dynamics, `evolve()`
implementation, Neurobiophysical Geometry experiments, edge mutation APIs,
custom HDP law implementation, streaming recorders (design only unless trivial
inspection surfaces).

### 2.2 v0.4.23 — EXACT REPRESENTATION + DEVELOPMENT SUBSTRATE

- Authoritative realized topology; backend-specific physical layouts only.
- Eliminate avoidable $O(N^2)$ storage and construction transients (W10/W11).
- Class / scalar parameter sharing where semantically valid.
- Observation-driven recording + streaming/decimated capture (§4.2).
- Authoritative edge selectors and immutable transforms with provenance (§4.2).
- Structured custom HDP/RBD law interface (§4.2; not project-specific controllers).
- Execution economics: step throughput, batched matched runs, memory preflight.
- **Minimal JDNA `evolve` substrate only if semantics and tests are complete**
  before merge — otherwise remain PROVISIONAL documentation.
- **No statistical approximation.** Bit-exact observables for every exact
  transformation.

### 2.3 v0.4.24 — BOUNDED AUGMENTATION + NEUROBIOPHYSICAL GEOMETRY

- $G(F, c, \epsilon)$ augmentation research (W16 §6).
- Pseudo-neurogeneration experiments under explicit error bounds.
- Statistical geometric augmentation with per-observable $(d, \epsilon)$.
- Scale / error / cost frontier measured on the W8 harness baseline.

The only release permitted to trade exactness for cost, because only here does
the equivalence infrastructure exist to bound it.

### 2.4 Mathematical north star (FUTURE / PROVISIONAL)

A JaxFNE model should distinguish:

| Layer | Role |
| --- | --- |
| model specification | what the scientist declares (incl. developmental rules) |
| state | $(X, H)$ and their dynamics |
| parameters | $W$, $\Theta$, plasticity coordinates |
| structure / geometry | $G$ — realized topology, positions, populations |
| sources | $Q = F_Q(X, H, W, G)$ |
| fields | $\Phi = F_\Phi(Q, G)$ |
| observations | probes and recorded outputs |

Each layer may change **only through an explicitly defined operation**. Do not
collapse biophysical state, plasticity, and structural development into one
variable class.

**State decomposition (provisional, not current TFNE implementation truth):**

$$\boxed{S = (X, H, W, G)}$$

- $X$: neural activity / membrane / spike state
- $H$: biophysical dependency state (RBS/RBD coordinates) — **not** structural
  topology
- $W$: mutable parameters / plasticity (HDP governs $\dot W$ where enabled)
- $G$: realized geometry, topology, developmental structure

**Provisional continuous-time form (FUTURE until formally defined and tested):**

$$\begin{aligned}
\dot X &= F_X(X, H, W, G, I) \\
\dot H &= F_H(X, H, W, G) \\
\dot W &= F_W(X, H, W, G) \quad \text{(HDP when enabled)} \\
\dot G \;/\; \text{events} &= F_G(X, H, W, G)
\end{aligned}$$

$$Q = F_Q(X, H, W, G), \quad \Phi = F_\Phi(Q, G), \quad Y = \mathrm{Probe}(\Phi, X, G)$$

$H \rightarrow \dot G$ is allowed (e.g. trophic / energetic state influencing
growth). Neuron birth, death, synapse creation, and geometry displacement
**change the represented system** ($G$), not merely its biophysical state ($H$).

**Developmental hierarchy (target, not implemented):**

$$\boxed{
\text{JDNA}
\rightarrow
\text{development}
\rightarrow
(X, H, W, G)
\rightarrow
\text{sources}
\rightarrow
\text{fields}
\rightarrow
\text{observations}
}$$

Do **not** promote $\dot G$ or `evolve()` to current implemented TFNE truth.
Mark FUTURE/PROVISIONAL until API, tests, and receipts exist.

### 2.5 Performance programme (dual evidence)

Two evidence sets govern performance priorities; neither alone is sufficient.

| Source | Dominant finding | Release |
| --- | --- | --- |
| W10/W11 (local) | dense `emitter.W` + construction transients are major $O(N^2)$ hazards | 0.4.23 representation |
| Jomission (downstream) | at dt=0.1 ms: integration steps, matched reruns, recording/host RAM dominate long runs | 0.4.23 execution economics |

**Jomission-observed cost ranking** (long-run dt=0.1 ms workloads): (1) step
count; (2) repeated matched trajectories; (3) recording/persistence; (4)
concurrency/host memory; (5) construction/compile; (6) source/field analysis.
W10/W11 findings remain authoritative for construction; do not let them subsume
the execution/recording programme.

**0.4.23 must optimize both:** (A) model representation/construction — remove
avoidable $O(N^2)$ resident and transient cost; (B) execution/experiment
economics — step throughput, batched matched simulations, streaming recording,
memory preflight, long-run persistence.

**W15. BMTK/SONATA architecture study (planning only).** Status: **PLAN**.
No SONATA import/export and no BMTK interoperability in v0.4.22. This item
records external architecture lessons that independently reinforce what W10/W11
measured inside JaxFNE. Sources: Allen Institute BMTK docs (build/simulate/analyse
separation; SONATA persistence; engine dispatch to NEURON/NEST/DiPDE; selective
recording; MPI parallelism at scale).

*What BMTK teaches (not what to copy wholesale).* BMTK delegates numerical
simulation to external engines. JaxFNE's differentiator is a **JAX-native,
composable** execution stack (`jit`, `scan`, `vmap`, autodiff, accelerators,
optimization) over the same scientific model. The transferable lesson is
**representation boundaries and backend specialization**, not engine delegation.

| BMTK idea | JaxFNE analogue | Priority |
| --- | --- | ---: |
| Separate build from simulation | `construct` → compact executable `Model` | Very high |
| Persistent network representation | canonical compact realized topology | Very high |
| Different engines by model regime | backend chosen by realized structure | Very high |
| SONATA interoperability | optional import/export boundary (later) | High |
| Selective recording | requested observations only | High |
| MPI parallelism | JAX sharding / batched independent runs (later) | Later |
| Multicompartment / point / population spectrum | variable biological detail in one representation | Already aligned |

*Six principles mapped to measured JaxFNE evidence.*

1. **Do not retain representations the selected backend will not read.** BMTK
   constructs once, stores, then simulates without rebuilding. W10/W11 showed the
   current anti-pattern: configuration → `{W_{N×N}, edge_list}` → choose one
   backend, with both often resident. Target:

   $$\text{configuration} \rightarrow \text{realized canonical topology}
   \rightarrow \text{backend-specific executable representation}$$

   Only the layout required by the selected backend should be resident during
   execution. This is likely the largest RAM opportunity (W10 headline).

2. **Backend selection should depend on realized topology, not merely N.** For
   genuinely dense connectivity, dense matmul $I = Ws$ can be the right
   accelerator workload. For bounded degree $E = NK_{\max} \ll N^2$, edge-list /
   segment execution is appropriate. Eventual selection should approximate
   $B^* = \arg\min_B C(B \mid N, E, \text{device}, \text{dtype}, \text{dynamics})$
   rather than a threshold rule dominated by N alone. Likely more important than
   adding another `jit` boundary.

3. **Separate logical scientific model from physical execution layout.** SONATA
   gives BMTK a stable representation independent of simulator backend. JaxFNE
   needs the same *idea* without necessarily adopting SONATA internally: an edge
   may be logically $(pre, post, w, \tau, d, r)$ while physically stored as
   $pre[E], post[E], w[E], class[E]$ plus shared $(\tau, d, r)[C]$ when
   class-shared — giving $O(Ed_\theta) \rightarrow O(E) + O(Cd_\theta)$ without
   changing the public scientific model. Maps directly onto W10 class-sharing
   candidates (`receptor_index`, `tau_ms`, `delay_steps`).

4. **Recording is observation-driven.** BMTK selects cells and variables to
   record. JaxFNE default recording is already $O(TN)$ not $O(TE)$, but the rule
   should be explicit: $\text{dynamic state} \neq \text{recorded state}$.
   Spikes as events/bools; population rates accumulated online; source/field
   summaries online; full trajectories optional; PSD/statistics incremental.
   At $dt = 0.1$ ms, one biological second is $10^4$ steps — recording policy
   becomes load-bearing at scale.

5. **Parallelism: independent batches first, domain decomposition later.** BMTK
   uses MPI across tasks. JaxFNE should prefer `vmap`/sharding across seeds,
   parameter sets, AGSDR candidates, perturbations, and conditions (no
   inter-network communication) before sharding one huge network. For a single
   large network, natural partitions are population → column → area; each device
   owns local $(X_d, H_d, E_d)$ and exchanges only cross-partition activity —
   conceptually domain decomposition, executed through XLA/JAX.

6. **Multi-resolution is a product direction, not a speed contest.** BMTK spans
   multicompartment, point-neuron, filter, and population models via different
   engines. JaxFNE can express different detail levels inside a common
   $(X, H, W, Q, \Phi)$ representation — eventually composed in one model (detailed
   local circuit, reduced surround, population-level distant areas, common
   source/field observation). Stronger than competing with NEST on point-neuron
   speed alone.

*Target performance architecture (v0.4.23 north star, gated on W8/W10/W11):*

$$\text{Specification} \rightarrow \text{canonical realized topology}
\rightarrow \text{backend-specific compact representation}
\rightarrow \text{one compiled transition} \rightarrow \texttt{lax.scan}
\rightarrow \text{requested observations only}$$

For bounded degree $E = NK$, target resident memory and step cost
$M = O(NK + Nd_X + Nd_H)$, $C_{\rm step} = O(NK + Nd_X + Nd_H)$, with **no
residual $N^2$ representation** when the realized topology is sparse. For
dense topology, retain dense execution when measured faster (W11 Result 4).

*Single headline lesson.*

$$\boxed{\text{scientific model specification should be independent of the
representation used to execute it efficiently}}$$

BMTK achieves this partly through SONATA plus specialized simulators. JaxFNE
should achieve it through **one scientific model → measured backend-specific JAX
layouts** — exactly what W10/W11 independently discovered.

*JaxFNE extension beyond BMTK/SONATA (research, not interoperability).* BMTK
separates **static** scientific specification from execution layout. JaxFNE
additionally targets specifications that may be **developmental** rather than
describing only a frozen realized network. Potential future boundaries:

- **SONATA / external static model** $\leftrightarrow$ **JaxFNE static
  realization** (import/export research question; W15 High priority, not 0.4.22).
- **JDNA** may encode **developmental rules** that SONATA need not represent.

This is a research question, not a current interoperability claim.

*v0.4.22 scope boundary.* Study and record only. Optional deliverable: a short
`artifacts/audit/bmtk_sonata_architecture_study.md` receipt linking BMTK docs to
W10/W11 cells. *v0.4.23 actionable carry-forward:* make realized topology
authoritative; treat dense / edge / class-shared layouts as execution
representations, not simultaneous permanent model truth; refuse contradicted

**W16. Scientific and developmental programme (planning only).** Status:
**PLAN**. Defines the second roadmap axis: models that develop, evolve, and
change scale. **Not implemented in v0.4.22.** Mathematical and API definitions
here are PROVISIONAL until backed by tests and receipts. See also §2.4 and §8
(scientific programme summary).

*Distinctions that must not be collapsed.*

| Concept | What it is | What it is not |
| --- | --- | --- |
| $H$ (RBS/RBD) | biophysical state of the **current** represented system | structural topology ($G$) |
| HDP | parameter dynamics $\dot W$ | neuron birth or edge creation |
| $G$ / structural events | changes **which** neurons, edges, geometry exist | another name for $H$ |
| `develop()` (JDNA, build-time) | **implemented** generative specification → `NeuronalTensor` | runtime structural neurogenesis |
| `evolve()` (future) | developmental update of specification or realization | shipped today |

**W16.1 Flexible biophysical state.** $H$ through RBS/RBD should let a model
introduce the biophysical coordinates required by the question without a new
simulator architecture each time:

$$\dot X = F_X(X, H, W, \ldots), \quad \dot H = F_H(X, H, W, \ldots)$$

$H$ may represent, where **explicitly defined**: ionic state; energetic /
resource state; synaptic state; adaptation; neuromodulation; shared
extracellular state; other declared biophysical coordinates. Ownership may
differ across synapse, neuron, population, area, and spatial field. **Do not
imply every model needs every $H$ coordinate.**

**W16.2 Source → field → probe (central scientific direction).** Neural and
biophysical dynamics feed a single defined computation:

$$\text{dynamics} \rightarrow \text{source} \rightarrow \text{field}
\rightarrow \text{probe} \rightarrow \text{observation}$$

Probes may yield spikes, population signals, LFP-like proxies, and — only where
the required forward model and calibration are defined — EEG/MEG or other
physical observations. Preserve **proxy ≠ calibrated physical measurement**.
Model state and physical observations are parts of one pipeline, not separate
ad-hoc analysis systems.

*Downstream candidates (0.4.23+, inspection-only in 0.4.22 if trivial):* source
contribution report by neuron/edge metadata; streaming spectral/band recorder;
observation manifest (source semantics, field operator, probe geometry,
filter/reference, claim level); matched source-ablation where mathematically valid.
Do not merge source and field.

**W16.3 Developmental / evolving models (JDNA roadmap extension).** Extend JDNA
beyond static specification. Conceptual future operation (syntax **not**
finalized):

$$\text{JDNA}_{t+1} = \mathrm{evolve}(\text{JDNA}_t, \text{state},
\text{environment}, \text{rules})$$

or equivalently $\text{JDNA}' = \mathrm{evolve}(\text{JDNA},
\text{observations/state}, \text{developmental rules})$.

Study operations: growth; pruning; replication; mutation; differentiation;
