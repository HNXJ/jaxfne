# JaxFNE post-0.4.21 reduction programme: v0.4.22 -> v0.4.24

Status: PLAN. Nothing in this file is a completed claim.
Audience: developers. Deliberately outside `docs/` and outside the mkdocs
`nav:`, so it is not a public surface. Do not link it from public docs.
Baseline: v0.4.21, published from `88235208950425ce76723115f1cb61fe3a828ab2`.

## 0. What "thinnest, flawless, bugless" has to mean here

"Flawless" is not a testable predicate, so this programme does not use it as an
acceptance criterion. It is decomposed into four things that can each fail:

1. **No silent scientific failure.** Every path that can swallow an error either
   raises, or records a counted, named rejection reason that reaches the caller.
2. **No unexplained canonical cost.** Every canonical-runtime allocation or
   operation scaling worse than the information it carries is classified, and
   every AVOIDABLE one is either reduced or justified in writing.
3. **No public surface promising what does not exist.** Rendered docs and public
   API describe implemented behaviour only.
4. **Observable equivalence under a declared tolerance.** Every reduction is
   accepted against a named observable and a stated epsilon, or is bit-exact.

A release is done when its gates pass with receipts, not when it feels clean.
`UNKNOWN` is never a pass. Same rule that governed the v0.4.21 seal.

### 1.1 Canonical connectivity holds two full representations

Recursive walk of model object state after
`construct(configuration().network(n=N).emitter().field().probe(n_contacts=4))`:

| N | model arrays | total | growth | dense `emitter.W` | edge-list E |
| --- | --- | --- | --- | --- | --- |
| 64 | 16 | 0.116 MB | - | 0.016 MB | 4,032 |
| 256 | 16 | 1.840 MB | 15.87x | 0.262 MB | 65,280 |
| 1024 | 16 | 29.381 MB | 15.97x | 4.194 MB | 1,047,552 |
| 2048 | 16 | 117.481 MB | 4.00x | 16.777 MB | 4,192,256 |

Observed `E = N(N-1)` exactly: the default `.network(n=N)` is all-to-all.
O(N^2) *at this configuration* is therefore intrinsic to the requested topology,
not a defect. The 4.00x-per-doubling growth is that topology's expected
signature, not evidence of waste.

Not yet explained: `RuntimeConfig.recurrent_backend` defaults to `"dense"`
(`jaxfne/_runtime_config.py:71`) and the dense kernel computes
`params.W @ state.spikes` (`jaxfne/emitters.py:4647`), yet `construct()` always
also materialises the edge list, which at N=2048 is the larger structure
(~100 MB of the 117 MB). `jaxfne/_model_simulate.py:218` states homeostasis is
edge-based and that `edge_list` always exists from `construct()`.

**Classification: UNKNOWN.** Resolving it is a v0.4.22 entry task, not a
v0.4.23 optimisation task: the classification decides whether any optimisation
is warranted at all.

### 1.1b Tensor-allocation map, N=1000 (the map that decides v0.4.23)

`construct(configuration().network(n=1000).emitter().field().probe(n_contacts=8))`.
"Distinct" is the count of unique values in the array, i.e. how much information
the allocation actually carries.

| tensor | shape | dtype | MB | distinct values |
| --- | --- | --- | --- | --- |
| `emitter.W` | (1000, 1000) | float32 | 4.000 | **3** |
| `edge_list.pre` | (999000,) | int32 | 3.996 | 1000 |
| `edge_list.post` | (999000,) | int32 | 3.996 | 1000 |
| `edge_list.weight` | (999000,) | float32 | 3.996 | **2** |
| `edge_list.receptor_index` | (999000,) | int32 | 3.996 | **2** |
| `edge_list.tau_ms` | (999000,) | float32 | 3.996 | **2** |
| `edge_list.delay_steps` | (999000,) | int32 | 3.996 | **1** |
| `positions` | (1000, 3) | float32 | 0.012 | 1000 |
| `emitter.{a,b,c,d,drive,sign,u0}` | (1000,) each | float32 | 0.004 each | 1-3 each |
| `emitter.v0` | (1000,) | float32 | 0.004 | 999 |
| **total persistent** | | | **28.020** | |

Reading of this map:

- **~16 MB of 28 MB (57%) is class-shared data materialised per edge.**
  `weight`, `receptor_index`, `tau_ms` carry 2 distinct values each; `delay_steps`
  carries **one** - 3.996 MB storing a single repeated integer. These are the
  `theta_class` + index case, not per-edge state.
- `emitter.W` carries 3 distinct values across 10^6 float32 entries.
- Per-neuron parameters are already small but equally class-shared: every one of
  `a,b,c,d,drive,sign,u0` has 1-3 distinct values. Only `v0` (999 distinct,
  jittered initial condition) is genuinely per-neuron.
- `pre`/`post` are structural. For all-to-all they are a deterministic
  enumeration and need not be stored at all.

Simulate-time recording, same network:

| duration / dt | T | recorded tensors | total |
| --- | --- | --- | --- |
| 100 ms / 0.1 ms | 1000 | `V_m`, `spikes`, `sources` at (T,N) float32 + `time_ms` | 12.004 MB |
| 200 ms / 0.5 ms | 400 | same | 4.802 MB |

Recording is O(TN), not O(TE) - the feared `T x E` edge-current traces are not
in the default path. One cheap win visible here: `spikes` is float32 at (T,N),
where bool or int8 would be 4x smaller.

### 1.1c Sparsity levers exist but are unreachable, silently inert, or additive

Bounded-degree connectivity is present and, once reachable, correct:
`_make_sparse_within_area_edges` builds an edge list directly from `p_connect`,
and connection rules support `max_in_degree` with spatially-localized sampling.
The 2026-09-08 measurement (superseding the earlier "100x sparsity request had
no effect" entry, which over-generalised from a single route) found the machinery
works but is gated behind three distinct silent-failure modes plus one design
decision.

**D1 -- `max_in_degree` is unreachable through the documented API.**
`_config.Configuration.connections()` always writes `"spatial_sigma": None` into
the rule entry (`jaxfne/_config.py:744`), so
`float(rule.get("spatial_sigma", 0.1))` in `jaxfne/connectivity.py:507` receives
`None`, not the default, and raises
`TypeError: float() argument must be a string or a real number, not 'NoneType'`.
Every `connections(..., max_in_degree=K)` call crashes unless the caller also
passes an undocumented `spatial_sigma=`. Classic dict-default-vs-explicit-None.

**D2 -- without a resolvable `mechanism=`, `max_in_degree` is ignored and the
rule doubles the network.** `_construct_core.py:658` only takes the
mechanism-aware compiler when *every* rule declares a resolvable mechanism;
otherwise `_compile_connection_rules` runs and drops `max_in_degree`. Measured
at N=1000, `connections(max_in_degree=100)` with no mechanism produced
E = 1,998,000 and max in-degree 1998 -- a 10x sparsity request yielded a 2x
*denser* network, with no warning.

**D3 -- `p_connect=0.0` is falsy and therefore ignored**, yielding full dense
N(N-1). A legitimate "suppress baseline recurrence" request cannot be expressed.

**D4 (design, not defect) -- `.connections()` is additive over an
unsuppressible dense default.** `max_in_degree` caps the *rule's* contribution
to exactly N*K, but the base recurrent set remains, so total
E = N(N-1) + N*K. Reaching E = O(N*K) today requires the accidental combination
`.connectivity(p_connect=0.001)` + `.connections(max_in_degree=K,
spatial_sigma=0.1)`.

Route dependence of `p_connect` at N=1000, p=0.01 (measured):

| route | E | verdict |
| --- | --- | --- |
| `.network(n=1000, p_connect=0.01)` | 999,000 | inert |
| `.column(...).connectivity(p_connect=0.01)` | 10,186 | effective |

`.network()` falls through to `make_eig_network` /
`_default_eig_connectivity`, which materialises dense all-to-all unconditionally
(`_construct_core.py:510-540`); a `RuntimeWarning` fires at N >= 5000 but only
warns. A recorded instance: 100,000 neurons with `p_connect=0.0005` still built
a dense (n,n) matrix (~40 GB) and ran ~370 s.

Bounded-degree scaling, once D1-D4 are worked around (measured, seed=1,
`.column()` route, `spatial_sigma=0.1`):

| N | p_connect | K_max | E | max in-deg | E/N | total | `emitter.W` |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1000 | 0.001 | 100 | 101,020 | 106 | 101 | 6.47 MB | 4.00 MB (62%) |
| 4000 | 0.001 | 100 | 415,845 | 113 | 104 | 74.16 MB | 64.00 MB (86%) |
| 1000 | 0.0 | 100 | 1,099,000 | 1099 | 1099 | 30.42 MB | 4.00 MB |
| 4000 | 0.0 | 100 | 16,396,000 | 4099 | 4099 | 457.68 MB | 64.00 MB |

E = O(N*K_max) is therefore already realised. The residual O(N^2) term is
`emitter.W` alone, and it dominates at 86% of construct memory by N=4000. It is
retained below `_SPARSE_DIRECT_N = 5000` (`jaxfne/_construct_population.py:279`)
by an explicitly tested invariant -- `test_below_threshold_keeps_dense_W`
(`tests/test_connectivity_scaling.py:96`) asserts the dense path is preserved.
Removing it means retiring a test that currently encodes the opposite intent,
which is a v0.4.23 decision, not a v0.4.22 one. **Do not delete that test yet.**
It is evidence of existing intentional semantics. W10 must first establish
`U_W` -- every reader of `emitter.W` -- and the exact replacement requirement
for each, before the invariant is retired.

**Consequent restatement of the programme headline.** v0.4.23 is not "make
bounded-degree connectivity edge-native" -- that exists and is correct. It is:

- v0.4.22: make the connectivity controls reachable (D1), composable (D4),
  and non-silent (D2, D3).
- v0.4.23: remove `emitter.W`, the last O(N^2) residue.

Two sit on scientific paths, confirmed at source:

  legitimately invalid null; the surviving count becomes the null N.

## 2. Sequencing rationale

Each release contains only changes whose risk class matches the evidence
available at that point.

- **v0.4.22 measures and de-risks.** Diagnostics and public surfaces, plus the
  classification and benchmark harness that justify later work. No
  representation changes; science bit-exact by construction.
- **v0.4.23 reduces representation.** The heavy engineering, gated on v0.4.22's
  classification and harness. Every item cites a measured before/after.
- **v0.4.24 approximates and proves.** The only release permitted to trade
  exactness for cost, because only here does the equivalence infrastructure
  exist to bound it.

Optimising first and measuring after is the failure mode this ordering exists
to prevent.

**W10. Tensor-allocation map as a repeatable tool.** Section 1.1b was produced
by hand; make it a script. For each persistent and each important transient

**The headline is not "W is dead" -- it is that both representations are always
materialised and exactly one is ever consumed.** On the dense backend the entire
edge list is unused (19.992 MB, 71.3% of M_persistent); on the edge_list backend
`emitter.W` is unused (4.000 MB, 62.1% of M_persistent). This resolves the W6
UNKNOWN as **AVOIDABLE**, by measurement rather than inspection. The 0.4.23 change
is therefore a construction-time decision -- do not materialise the representation
the selected backend will not read -- not a dynamics rewrite. The sparse-direct
path already does exactly this above `_SPARSE_DIRECT_N`, returning a (0,0)
placeholder W; the gap is that it is gated off below the threshold.

`receptor_index` carries no dynamical content **by design, not by defect**:
swapping it between AMPA(0) and GABA_A(1) across all 35,960 edges of a two-mechanism
edge_list model leaves V_m bit-identical, while the same swap on `tau_ms` changes it
(control). `docs/appendix/fundamental_laws.md:180` defines receptors *as* decay
constants and line 190 explicitly bounds out reversal-potential and NMDA voltage
dependence. It is a provenance label, so it is a clean class-sharing candidate
rather than a bug -- but it must not be deleted, only shared.

*Two cautions carried into 0.4.23.*

1. `delay_steps` on the dense path raises when perturbed rather than changing the
   output. A raise proves the value is *read* (a validation check) but not that
   dynamics consume it. The tool records this as `read_but_unclassified` rather
   than counting it as dynamics-critical; classifying it is outstanding.
2. Persistent memory is not the binding constraint at this scale. Measured
   M_peak (RSS delta) is 306-314 MB against M_persistent of 6.4-28.0 MB and
   M_recording of 1.0 MB, so M_temporary dominates by an order of magnitude --
   it includes XLA compilation, so treat it as an upper bound, but a 0.4.23

**Result 1 -- bounded fan-in bounds E, and does not bound memory.** M_W is
4 N^2 bytes in every cell, independent of K_max, because `emitter.W` is
materialized dense unconditionally:

| N | K_max | E | M_W | M_edge | M_persistent | M_resident / M_logical |
|---|---|---|---|---|---|---|
| 1000 | 25 | 25,000 | 4.00 MB | 0.60 MB | 4.64 MB | 1.16 |
| 5000 | 25 | 125,000 | 100.0 MB | 3.00 MB | 103.2 MB | 1.03 |
| 10000 | 25 | 250,000 | 400.0 MB | 6.00 MB | 406.4 MB | 1.016 |
| 10000 | 200 | 2,000,000 | 400.0 MB | 48.0 MB | 448.4 MB | 1.12 |

At N = 10000, K_max = 25 the *entire* declared topology occupies 6 MB and the
model occupies 406 MB. Asking for a fan-in of 25 buys a 1.6% saving over the
dense equivalent. The ratio moves the wrong way with N: 1.16 at N = 1000,
1.016 at N = 10000, because the numerator's O(N K) is outrun by the
denominator's O(N^2). This is the quantitative form of the W10 finding
(W != R(edge list), so neither is a cache of the other) and it is the whole
case for v0.4.23: no reduction of the edge representation can matter while W
is allocated dense.

**Result 2 -- construction transiently costs ~6 dense N x N arrays.**
M_peak(construct) has a floor of 194-215 MB in every cell including N = 100,
which is XLA runtime initialization rather than model memory (*derived*, from
the N = 100 cells where the model is 0.1-0.3 MB). Net of that floor:

| N | K_max | M_peak(construct) net | / M_W | t_construct |
|---|---|---|---|---|
| 5000 | 25 | 451 MB | 4.5 | 9.15 s |
| 10000 | 25 | 2289 MB | 5.7 | 19.9 s |
| 10000 | 200 | 2321 MB | 5.8 | 25.6 s |

Flat in K_max, quadratic in N. Building a model whose declared content is
6 MB requires ~2.3 GB of transient. M_temporary, not M_persistent, is what
sets the largest N this library can construct at all.

**Result 3 -- B is not an independent dimension, and the substitution is
silent.** In all 16 cells with a materialized rule (K_max != inf), the
requested backend was overridden to `edge_list`
(`_construct_core.py:577,713`). The two B columns are byte-identical and
time-identical throughout: the atlas is really (N, K_max), and any published
table with a `dense` row at bounded K_max would be reporting a backend that
did not run.

The override is *correct* -- a dense W does not carry rule edges, so running
dense would silently drop them -- but it is a W13-class defect in how it is
delivered. `cfg.metadata` distinguishes an explicit `.runtime(recurrent_backend=

`{'recurrent_backend': 'dense'}` explicit), so the code *can* tell a
contradicted request from an absent one and currently does not. Proposed
repair, matching the W13 contract already adopted: refuse an explicit `dense`
request that a materialized rule contradicts, and leave the unset default to
be resolved silently as now. Not applied -- it is a public behaviour change
and is listed here for decision.

crossover must be measured, not assumed.

*Sparsity that does not engage.* The levers exist; the gates defeat them. Lower
or remove `_SPARSE_DIRECT_N = 5000` so a sparse request at N=1000 yields a
sparse allocation, and fix the routing so `p_connect` is either honoured or
rejected loudly rather than being silently inert on the default builder. A
sparsity request that changes nothing is worse than an unsupported one, because
the caller believes it worked. The small-N dense path was kept deliberately so
W-inspecting tests stay exact - those tests must be migrated, not deleted.

Target runtime form for bounded degree `E <= N*K_max`: immutable structure
`(src, dst, type, delay, theta_class, indices)` plus mutable state
`(X, H_local, H_shared, W_mutable, B, K)`, giving a step cost of
`O(N*d_X + N*d_H + E + E_p)`, which is `O(N)` for fixed `K_max, d_X, d_H`.

**Parameter sharing.** 1.1b already shows the size of this prize: at N=1000,
~16 MB of 28 MB is class-shared data materialised per edge, and `delay_steps`
alone is 3.996 MB holding one distinct value. Classify every per-neuron /
per-edge parameter as
GLOBAL / CELL_TYPE / POPULATION / AREA / NEURON / EDGE. Where semantically
shared, store once and gather or broadcast at execution rather than
materialising N or E copies. Applies to emitter parameters, H/RBD coefficients,
HDP coefficients, synaptic kinetics, delay classes, field/source coefficients,
optimizer state. Bit-exact equivalence required.

**H / RBS / RBD.** Establish H dimension and ownership (synapse, neuron,
population, area, shared extracellular field). For each H coordinate ask whether
`F_X`, `F_H`, `F_W`, or any requested observable depends on it, and build the
observable-specific importance test `delta_jk = d_j(O_j(M), O_j(M^-k))`. Remove
or share computationally redundant *representation*; do not delete biologically
meaningful state on intuition. A coordinate no observable depends on is a
representation question, not a biology question - but that distinction must be
argued in writing per coordinate.

**HDP.** Update only mutable parameters actually enabled. Null HDP must remain
`W(t) = W(0)` bit-exact, as a mechanical test rather than a convention. Avoid
allocating dense mutable `W` when weights are shared, plasticity is disabled,
only a subset of edges is plastic, or parameter classes reduce to indices plus
shared values.

**Delays / history.** Derive the actual lower bound from the delay structure
rather than allocating for a nominal maximum. Investigate delay-class grouping,
compact ring buffers, active-delay sets, shared delay classes. Continuation
equivalence stays bit-exact wherever currently promised.

**Recording.** Enforce `dynamic state != requested observation`. Nothing stores
a full trajectory unless requested. Audit T x N, T x E, T x H, and field
histories. The known E/I executed-current issue is in scope: provide online
`I_E(t,n)` and `I_I(t,n)` at O(TN) requested storage instead of O(TE)
edge-current traces, preserving exact offline equivalence where feasible and
declaring the tolerance where not.

### 4.3 Acceptance gates

- Every merged item reports `speedup = t_before / t_after` and
  `memory_reduction = M_before / M_after` from the W8 harness on one machine.
- No optimisation merged without a measured improvement. An item that is correct
  but not faster is reverted or documented as a correctness change.
- Bit-exact observables for all exact transformations. No approximations here.
- Mechanical guards: canonical sparse construction must not allocate N x N; null
  HDP must not allocate mutable state; recording-off must not materialise
  recording arrays; shared parameters must not expand; online E/I current equals
  offline edge reduction.
- Full release gate chain as in 3.3.

## 5. v0.4.24 - Bounded approximation and final audit

Theme: the only release permitted to trade exactness for cost, and only with a
declared bound.

### 5.1 Work items

**Fields / LFP proxies.** Audit source/field computation for unnecessary
pairwise work. Where spatial kernels permit, evaluate neighbour cutoff, grouped
sources, convolution/grid methods, tree/FMM-like approximation, and low-rank
approximation against declared field error. Do not weaken the existing truth
separations: `Q != I_syn`, and proxy != calibrated measurement.

**JAX execution.** Profile; do not guess. Inspect JIT boundaries, scan, vmap,
segment ops, scatter/gather, BCOO/sparse, buffer donation, remat/checkpointing,
host-device transfers, Python loops, shape-polymorphism recompilation, dtype,
static arguments. Additional JIT is not automatically faster; measure before
adding any. Prefer one compiled transition over nested fragmented JIT where the
measurement supports it.

**Scientific equivalence.** Per-observable acceptance over `V_m`, spikes, rates,
ISI, H, W, delay arrivals, continuation, source, field, and PSD where relevant.
Exact transformations: bit-exact. Approximations: a declared
`d(O_before, O_after) <= epsilon`, with `d` and `epsilon` named per observable
*before* the approximation is accepted. "99% accurate" is not an acceptance
criterion and is accepted nowhere in this programme.

**Fresh adversarial core audit.** A critic that reads code, not only tests,
hunting: avoidable O(N^2), silent exceptions, hidden dense allocations, Python
loops, recompilation, duplicated parameters, duplicated H/HDP state, unnecessary
recordings, host transfers, unverified approximations, stubs, and public
unfinished claims. Independence matters: the implementer should not be the sole
auditor. That was the one acknowledged gap in the v0.4.21 seal and should not
repeat at the end of the programme.

### 5.2 Exit criteria for the programme

- Every canonical avoidable O(N^2) path removed or explained in writing.
- Zero silent scientific failure paths.
- Zero public surface promising unimplemented behaviour.
- Every approximation carries an observable, a metric, and an epsilon.
- Benchmarks show the cumulative before/after from the v0.4.21 baseline.
- Full gate chain plus an independent critic pass.

## 6. Risk register

| Risk | Why it bites | Mitigation |
| --- | --- | --- |
| Optimising a path that was never hot | Wasted risk on canonical science code | W8 harness first; no change without a baseline number |
| Treating all-to-all O(N^2) as a defect | It is the requested topology; "fixing" it changes meaning | Classification separates topology cost from representation waste |
| Deleting H coordinates that carry biology | Silent scientific loss, hard to detect downstream | Observable-specific importance test plus a written per-coordinate argument |
| Broad-handler cleanup breaking optional paths | `vis/` fallbacks exist for real reasons | Classify before touching; `vis/` last; narrow types rather than delete |
| Benchmarks across machines | Comparison is void | Same machine and environment, recorded in the receipt |
| 0.4.23 work merged into 0.4.22 | Loses the risk separation the sequencing exists for | 0.4.22 non-goals are explicit above |

## 7. Standing conventions for this programme

- `UNKNOWN` is not a pass, at any stage.
- Execution is not verification; a command plus its output is the receipt.
- No performance claim without a measured before and after on one machine.
- No approximation without a named observable, metric, and epsilon.
- Public docs describe implemented behaviour; private tallies hold the rest.
- Releases follow the v0.4.21 artifact-provenance chain: one retained build,
  a generated manifest, a hash-guarded publish, no rebuild.
