# Replication dashboard: design

A static, interactive page of the replication programme (release plan 0.5.6–0.5.10). It is
published on GitHub Pages at `/dashboard/`, separate from the Read the Docs site, and it
shows scored results only from committed evidence.

## Rules

1. **No verdict is computed in the page.** Every verdict and number comes from a scorer JSON
   committed on a lane branch at a named SHA. The generator copies values, it never re-scores.
2. **Failures have the same prominence as passes** (B2). A failed criterion shows its value,
   its criterion and its reason.
3. **Every number links to its evidence**: `https://github.com/hnxj/jaxfne/blob/<sha>/<path>`.
4. **One data file.** `dashboard/data/replications.json` is generated by
   `scripts/build_dashboard_data.py` from `dashboard/sources.json`. `--check` fails when the
   committed file is stale. Hand edits to the data file are refused by the check.
5. **Static.** `index.html`, `app.js`, `style.css` and the data file. No build step, no
   framework. One pinned library: Plotly (`plotly.js-dist-min@2.35.2`, jsdelivr).

## Files

| Path | Owner | Content |
|---|---|---|
| `dashboard/DESIGN.md` | dispatcher | this file |
| `dashboard/sources.json` | dispatcher | papers, preregs, criteria, series specs; the scientific meaning lives here |
| `dashboard/data/replications.sample.json` | dispatcher | hand-written example of the data contract (`"sample": true`) for building the page |
| `scripts/build_dashboard_data.py` | worker | sources.json + lane JSONs (`git show <sha>:<path>`) → `dashboard/data/replications.json` |
| `tests/test_dashboard_data.py` | worker | generator tests |
| `dashboard/index.html`, `app.js`, `style.css` | opencode | the page |

## Data contract (`replications.json`, schema `jaxfne-replications/2`)

Schema 2 (Hamm 2026-10-12, `ARCHITECTURE_v2.md`) adds per paper `class` (verified | partial |
not reproduced | demonstration | in progress), `question`, `page` (`models/<id>.md`, rendered with marked and
KaTeX), per criterion `paper_value` (text, or null where the paper gives none), and a top-level
`roadmap` list of `{release, model, needs}`. The generator refuses an unknown class, a
demonstration with a verdict, a scored class without a preregistration, and a named page that
does not exist. `verdict` is null for a demonstration. An in-progress paper carries no verdict and
needs a non-empty `stage`; it needs no signed preregistration, since the scored-class rule applies
to verified, partial and not reproduced only. Static PNGs of every chart come from
`scripts/build_dashboard_figures.py` (`dashboard/figures/`, manifest of chart-data hashes;
`--check` in the workflow).

## Layout

Desktop at 1440 px; one column at 390 px with no horizontal scroll. Hash-routed tabs:

1. **Header.** "jaxfne replications", generated time (UTC) and build dev SHA, links to the Read
   the Docs site and to `artifacts/etudes/REPLICATIONS.md`, a sample banner when `sample` is
   true, and the tabs.
2. **Overview** (`#overview`, default). KPI cards: models per class and the preregistered
   criteria pass / fail / pending (demonstrations and in-progress papers excluded). Then the model cards grouped by
   class, each with its class chip, its verdict chip where one exists, and its question.
3. **Models** (`#models`; one model at `#model/<id>`; v1 links `#<id>` still open it): title,
   citation, class chip beside the preregistered verdict, stage track, code SHA, summary; the
   model page (question, formulation, implementation, deviations and limitations, reproduce);
   then the criteria table (paper value beside ours), figures (Plotly with the static PNG and a
   data table under each), sensitivity, preregistrations and open items.
4. **Validation** (`#validation`): every criterion across models in one table, filtered by
   verdict.
5. **Roadmap** (`#roadmap`): planned models by release.
6. **Method** (`#method`): the class definitions and the rules of this file.
7. **Footer.** "Failures are kept with the same prominence as passes (B2)."

## Visual style

- Sans-serif: Arial, Helvetica, DejaVu Sans. Body 15 px, tables 14 px, captions 13 px.
- Series colors in order: `#1565c0`, `#ff9800`, `#00acc1`, `#e53935`; fifth and sixth
  (`#4caf50`, `#8e24aa`) only with a second cue (dash or marker).
- Verdict chips never rely on color alone: text plus symbol. pass `✓ pass` on `#1565c0`;
  fail `✗ fail` on `#ff9800` with dark text; pending `… pending` and incomplete
  `◌ incomplete` on `#e0e0e0`. Paper verdicts use the same mapping.
- Grounds: white page, cards on `#e9f5fc`; threshold lines and bands in gold `#cfb87c`.
- Dark theme by `prefers-color-scheme`, with contrast at least 4.5:1 for text.
- Plotly: no top or right axis lines, frameless legend, axis labels with units, `responsive`.
- Chart traces in one group share a color; seeds differ by dash or marker.

## Publishing

`gh-pages` holds the old MkDocs build (v0.4.20) at the site root. The dashboard goes to
`gh-pages:/dashboard/` only, and nothing else on the branch changes (Hamm 2026-10-12). The
`Dashboard` workflow publishes it on each dev push that touches `dashboard/` or the generator,
after `build_dashboard_data.py --check` passes. URL: https://hnxj.github.io/jaxfne/dashboard/.

Do not run `mkdocs gh-deploy` against this repository: it replaces the whole gh-pages tree and
would delete `/dashboard/`.

Updating: change `sources.json` (for a new score, its lane SHA and file), run
`python scripts/build_dashboard_data.py`, then `python scripts/build_dashboard_figures.py`,
commit the sources, the data file and `dashboard/figures/`, push to dev.
